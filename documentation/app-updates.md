# Проверка обновлений с GitHub

В **Настройки модификации → Общее** есть переключатель
**«Проверять обновления с GitHub»**. Он включён по умолчанию, включая обновление
со старой версии приложения. Ручная проверка работает и при выключенном
переключателе: **Настройки → О программе → Проверить обновления**, после
«Поддержать разработку».

Проверка использует публичный репозиторий
[HDDen/meshcore-open](https://github.com/HDDen/meshcore-open/releases), без токена.
GitHub `/releases/latest` выбирает опубликованный стабильный релиз; черновики
и релизы с флагом prerelease не предлагаются. Название и числовая версия тега
не сравниваются.

## Что считается обновлением

Приложение разрешает тег релиза в конкретный SHA через GitHub API, затем
сравнивает историю `установленный SHA...SHA релиза`:

- `ahead` — доступно обновление;
- одинаковые SHA, `identical` или `behind` — обновление не требуется;
- `diverged` или недоступный коммит — ошибка с причиной; свежесть не выдумывается.

Дата публикации и дата коммита не определяют порядок версий. SHA приложения
должен быть опубликован в этом репозитории и иметь общую историю с релизом.
Сборка из другой ветки может получить сообщение о разошедшейся истории.

## Интервал и сообщения

- Интервал — 24 часа от начала последней попытки, включая сетевые ошибки.
  Время сохраняется после перезапуска. Ручная проверка переносит следующую
  автоматическую на сутки; одновременные запросы объединяются.
- Автоматические проверки запускаются при открытии/возврате приложения и по
  таймеру, пока оно активно. В фоне нет таймера проверки, OS alarm или wake lock.
  Если срок наступил во сне, проверка произойдёт после возвращения в приложение.
- Новое обновление вызывает информационное уведомление внизу. Нажатие открывает
  браузер со страницей релизов; плитка ручной проверки становится ссылкой на неё.
  Этот результат сохраняется для текущей сборки после перезапуска; смена SHA
  приложения/модуля или dirty-флагов сбрасывает положительный кэш.
- Автоматический отрицательный результат не показывает уведомлений; ручной
  показывает «Обновления не найдены». Информационные уведомления используют
  обычные цвета темы приложения; нажатие на «Обновления не найдены» закрывает его.
  Ошибка показывает красное уведомление с причиной. Нажатие копирует заголовок
  и причину в буфер обмена и закрывает уведомление. Результат, полученный при неактивном приложении, показывается
  после возврата. Сетевая ошибка не стирает уже найденное обновление.

## SHA при сборке

Существующий wrapper `lib_serv/tools/release_build.dart` автоматически читает
полный SHA приложения и приватного модуля и передаёт их Flutter:
`MCO_APP_COMMIT`, `MCO_MODULE_COMMIT`, `MCO_APP_DIRTY`, `MCO_MODULE_DIRTY`.
Ручного редактирования SHA перед сборкой не требуется. Обычные параметры своей
сборки оставляйте после разделителя `--`, например:

```text
dart run lib_serv/tools/release_build.dart apk -- --dart-define=MCO_SERV=true
dart run lib_serv/tools/release_build.dart ios -- --dart-define=MCO_SERV=true
```

Команда `ios` выполняется на macOS и создаёт неподписанный Runner.app;
для подписанного архива используйте существующую цель `ipa` со своими параметрами.
Остальные цели wrapper: appbundle, macos, windows, linux. Повторную сборку того же
коммита/версии wrapper по-прежнему защищает от перезаписи symbols; подробности
сохранения символов — в существующей инструкции сборки.

Константы находятся в `lib/utils/app_build_info.dart`. SHA приложения отображается
под версией в окне «О программе». Прямой `flutter run/build` не читает Git:
если константа не передана, показывается «не указан», а проверка сообщает причину.
Wrapper для web не применяется.

### Debug из VSCode

Для корневых конфигураций `meshcore-open` (debug/profile/release) настроен
`preLaunchTask` **mcoa: prepare Git build info** из `.vscode/tasks.json`.
Перед запуском он вызывает `dart tool/write_build_info.dart`, который читает
HEAD/dirty приложения и отдельного репозитория lib_serv, затем атомарно записывает
`.dart_tool/mco_build_info.json`. Flutter получает файл через
`--dart-define-from-file`. Git и Dart должны быть доступны в PATH VSCode.

Личный `.vscode/launch.json` игнорируется Git. Текущие три корневые конфигурации
настроены локально; для нового checkout используйте `.vscode/launch.example.json`
как образец либо перенесите из него `preLaunchTask` и define-file в свою
конфигурацию, сохранив остальные параметры. Старые конфигурации `.kilo/worktrees`
автоматически не перенастраиваются.

После изменения SHA/define нужен полный Stop и новый F5; hot reload/restart
не обновляет параметры компиляции. Инструмент генерации агентом не запускался.
Если задача не смогла прочитать Git, исправьте причину, не выбирая Debug Anyway
с устаревшим файлом. Наличие SHA не делает локальный неопубликованный коммит
доступным GitHub: в таком случае проверка отдельно сообщает об этом.

Для запуска из терминала сначала выполните `dart tool/write_build_info.dart`,
затем добавьте `--dart-define-from-file=.dart_tool/mco_build_info.json` к своему
`flutter run`. Генерируемый файл игнорируется Git и не содержит ключей/лицензий.

Тег релиза должен указывать на коммит, из которого собран опубликованный файл.
SHA описывает закоммиченную основу; при незакоммиченных изменениях wrapper
дополнительно фиксирует dirty-флаги. Сравнение публичной истории не обнаруживает
замену бинарника под тем же SHA, отдельное изменение приватного модуля или
нативной библиотеки. Учитывайте это при публикации нового релиза.

## Проверки

Агент проверки не запускал. Локализации добавлены в ARB en/ru.

```powershell
Set-Location O:\_git\meshcore-open
flutter gen-l10n
$updateTests = @(
  'test/tool/build_info_writer_test.dart'
  'test/services/github_release_check_test.dart'
  'test/services/app_update_service_test.dart'
  'test/widgets/app_update_controls_test.dart'
  'test/services/app_settings_power_baseline_test.dart'
)
flutter test @updateTests --exclude-tags=slow --reporter expanded
flutter analyze
```

На устройстве проверить ручную проверку с интернетом и без него, переход по
уведомлению/плитке в браузер, сохранение выключенного переключателя и SHA в
окне «О программе». Для определения обновления нужен SHA, доступный на GitHub.
