# Диагностический опыт CPU-off на Android

Для проверки влияния постоянного CPU wake lock добавлен параметр сборки
`MCO_DIAGNOSTIC_CPU_OFF`. По умолчанию он равен `false`: обычная Android-служба
сохраняет прежнее удержание, пока пользователь не включит рабочую группу [сна CPU](android-cpu-sleep.md).

При `--dart-define=MCO_DIAGNOSTIC_CPU_OFF=true` служба запускается с
`ForegroundTaskOptions.allowWakeLock=false`. Это статический диагностический
опыт, отдельный от четырнадцати параметров энергосбережения приложения.
Управление находится в `lib/helpers/background_task_options.dart`.

Интервалы repeat/heartbeat по 5 секунд, wall-clock timeout 20 секунд, владельцы
службы, удержание Flutter engine, Wi-Fi lock и BLE priority сохраняют прежние
правила. Сам foreground service продолжает запускаться; отключается разрешение
плагину держать CPU постоянно. Другие владельцы wake lock в системе могут
препятствовать сну независимо от этого параметра.

Параметр применяется только в Android-ветке инициализации `BackgroundService`.
Для проверки нужен новый APK; переключение профиля энергосбережения или горячая
перезагрузка Dart не изменяет уже работающую нативную службу. После установки
каждого варианта остановить приложение и затем открыть его вручную:

```powershell
adb shell am force-stop com.meshcore.mcoadvanced
```

Команда остановит приложение и соединение; данные сохраняются. После ручного
запуска подключить ноду заново. В варианте CPU-off при инициализации в журнале
`Background` появляется `Diagnostic CPU-off: plugin wake lock disabled; heartbeat unchanged`.
Снятие реального lock и сон CPU проверяются на устройстве, а не по этой строке.

## Проверки исходного и диагностического вариантов

```powershell
flutter test test/services/background_activity_baseline_test.dart test/services/background_cpu_diagnostic_test.dart --reporter expanded
flutter test test/services/background_cpu_diagnostic_test.dart --dart-define=MCO_DIAGNOSTIC_CPU_OFF=true --reporter expanded
flutter analyze
```

Первый вызов сохраняет исходные инварианты, включая включённый CPU lock по
умолчанию. Второй проверяет реально скомпилированный диагностический вариант;
исходный baseline с требованием `allowWakeLock=true` в него не включается.
Новые проверки сравнивают остальные параметры службы, запуск/повторный запуск,
heartbeat, независимых владельцев и инертность не-Android ветки.

Предварительный baseline службы владелец подтвердил: 7 тестов прошли.
Итоговый пакет с новыми проверками и опыт на устройстве пока ожидают подтверждения.

## Сборка публичного приложения

Сохранить одинаковые зависимости и профиль сборки для обоих вариантов. Пример
обычного APK без локального LLM-перевода:

```powershell
flutter build apk --release --split-per-abi --dart-define=MESHCORE_ENABLE_TRANSLATION=false --dart-define=MCO_DIAGNOSTIC_CPU_OFF=false
```

Для диагностического варианта:

```powershell
flutter build apk --release --split-per-abi --dart-define=MESHCORE_ENABLE_TRANSLATION=false --dart-define=MCO_DIAGNOSTIC_CPU_OFF=true
```

Сохранить каждый APK отдельно перед следующей сборкой. Для премиум-сборок
использовать штатную приватную release-обёртку и её учёт символов.
Отдельная пересборка Go/native-библиотек из-за этого Dart-изменения не требуется.

## Что проверять на телефоне

Сравнивать обычный вариант и CPU-off при одинаковом профиле приложения,
ОС-ограничениях, подключении и длительности. Отдельно фиксировать сообщения,
приходящие с выключенным экраном, переподключения и уведомления о разрыве.
После сна прежний wall-clock watchdog может ошибочно сообщить о разрыве;
его изменение не включено в опыт, чтобы сохранить один проверяемый фактор.

Меньший расход при пропавшей доставке не считается приемлемым результатом.
Отсутствие дополнительного suspend не доказывает бесполезность CPU-off: сначала
нужно проверить остальные app/kernel locks. Экономия и надёжность этого режима
проверены лишь первым диагностическим опытом; новые defaults не вводятся.
Рабочая CPU-политика реализована отдельно и ещё ожидает аппаратной приёмки.
После её первого использования обычный профиль может держать собственный
`mcoa:cpu-policy` вместо прежнего тега плагина; сравнивать нужно оба тега.
