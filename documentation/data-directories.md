# Папки данных и параметры ярлыков

## Поддерживаемые платформы

| Платформа | Каталог по умолчанию | `--data-dir` |
|---|---|---|
| Windows | `userdata` рядом с `.exe` | Поддерживается |
| Linux, включая AppImage | `$XDG_DATA_HOME/mcoa/userdata` либо `~/.local/share/mcoa/userdata` | Поддерживается |
| macOS | Системный Application Support | Сейчас игнорируется |
| Android / iOS / Web | Системное хранилище приложения | Не поддерживается |

На Linux учитывается только абсолютный `XDG_DATA_HOME`. При отсутствующем или
относительном значении используется абсолютный `HOME` и `.local/share` внутри
него. Установка приложения в `/opt` не требует прав root для хранения данных.
Разные Linux-копии без аргументов используют один пользовательский профиль.
Для нескольких одновременно работающих экземпляров задайте разные профили.

## Общий синтаксис

Обе формы равнозначны:

```text
--data-dir=/полный/путь
--data-dir /полный/путь
```

Последнее указание параметра побеждает. Пустой путь — ошибка запуска. Просто
добавить путь без `--data-dir` недостаточно: такой аргумент не выбирает профиль.

Относительный путь считается **от каталога исполняемого файла**, а не от текущего
рабочего каталога и не от местоположения ярлыка. Для AppImage это каталог внешнего
файла `.AppImage`, а не временная точка монтирования. Например, при запуске
`/opt/mcoa/mco_advanced --data-dir=profiles/radio` данные окажутся в
`/opt/mcoa/profiles/radio`: для `/opt` выбирайте абсолютный пользовательский путь.
Чтобы явно сохранить прежний переносимый режим, используйте `--data-dir=userdata`.

В выбранной папке находятся `support`, `cache`, `temp`, `documents` и файл
блокировки `profile.lock`. Профиль должен быть доступен пользователю для записи.
Копировать его вручную следует при закрытом приложении. Два процесса не могут
одновременно использовать один профиль. Настройка рабочего каталога ярлыка
(`Start in` / `Path=`) не заменяет `--data-dir`.

## Windows: ярлык и терминал

В поле «Объект» ярлыка `.lnk`:

```text
"D:\Apps\MCOa\mco_advanced.exe" --data-dir="E:\MCOa Profiles\radio-868"
```

Эквивалент с отдельным аргументом:

```text
"D:\Apps\MCOa\mco_advanced.exe" --data-dir "E:\MCOa Profiles\radio-868"
```

Относительный путь:

```text
"D:\Apps\MCOa\mco_advanced.exe" --data-dir=profiles\radio-868
```

Это `D:\Apps\MCOa\profiles\radio-868`. Не добавляйте завершающий обратный
слеш перед закрывающей кавычкой. Переменные вроде `%USERPROFILE%` само приложение
не раскрывает: используйте полный путь либо раскрывайте переменную в оболочке.

## Linux: терминал

```sh
/opt/mcoa/mco_advanced --data-dir="$HOME/MCOa Profiles/radio-868"
/opt/mcoa/mco_advanced --data-dir "$HOME/MCOa Profiles/radio-868"
/home/alice/Apps/MCOa.AppImage --data-dir=/home/alice/MCOa/radio-868
```

Здесь `$HOME` раскрывается оболочкой. Само приложение не раскрывает `$HOME`,
`${HOME}` или `~` в аргументе.

Относительный путь для переносимого каталога, доступного для записи:

```sh
/home/alice/Apps/mco_advanced --data-dir=profiles/radio-868
```

Получится `/home/alice/Apps/profiles/radio-868`.

## Linux: ярлык `.desktop`

Например, `~/.local/share/applications/mcoa-radio.desktop`:

```ini
[Desktop Entry]
Type=Application
Name=MCOa — radio-868
Exec=/opt/mcoa/mco_advanced "--data-dir=/home/alice/MCOa Profiles/radio-868"
Terminal=false
Categories=Utility;
```

Или с отдельным аргументом:

```ini
Exec=/opt/mcoa/mco_advanced --data-dir "/home/alice/MCOa Profiles/radio-868"
```

Для AppImage замените исполняемый файл полным путём к `.AppImage`. Относительный
профиль задаётся так: `Exec=/home/alice/Apps/MCOa.AppImage --data-dir=profiles/radio`.

`Exec=` не является командой shell: не рассчитывайте на раскрытие `$HOME` или
`~`. Укажите настоящий абсолютный путь. Аргумент с пробелами заключайте целиком
в двойные кавычки. Литерал `%` в пути записывается как `%%`. См.
[спецификацию Desktop Entry](https://specifications.freedesktop.org/desktop-entry/latest/exec-variables.html).

Linux runner и AppImage AppRun передают аргументы Dart без удаления: AppRun
использует `"$@"`. Обе формы параметра разбираются приложением одинаково.

## Перенос существующих данных Linux

При первом запуске с новой пустой папкой приложение сначала ищет прежнюю
`userdata` рядом с запускаемым bundle/AppImage. Если находит данные, предлагает
скопировать их в выбранную пользовательскую папку и показывает исходные пути.
Копирование включает настройки, базы, кэш, временные файлы и документы.
Исходная папка не изменяется и автоматически не удаляется; доступ на запись
в `/opt` для переноса не нужен. Перед переносом закройте другие копии приложения.

Если старой portable-папки нет, работает прежнее предложение перенести данные
из системных каталогов предыдущих версий. Заполненный целевой профиль не
перезаписывается и не объединяется автоматически. После переноса профиля для
дополнительных ключей может потребоваться пароль их хранилища.

Если нужно продолжить работу с существующей папкой без переноса, задайте её
явно: `--data-dir=/старый/путь/userdata` (нужен доступ на запись).

## macOS

Переопределение папки через аргументы пока не реализовано. Ни запуск внутреннего
бинарника `.app`, ни `open -a … --args --data-dir=…` не меняют её расположение.
Системный каталог приложения остаётся пользовательским; перенос рядом с `.app`
не применяется.
