# Настройки контактов в SQLite

На Android, iOS, Windows, Linux и macOS используется общая база
`message_history.sqlite` в каталоге данных приложения. Текущая версия схемы — 3.

## Существующие таблицы

Ниже перечислены прикладные таблицы; внутренние таблицы SQLite опущены.

| Данные | Таблицы |
|---|---|
| Сообщения и служебные метаданные истории | `history_messages`, `history_metadata`, `legacy_rejected_messages` |
| Контакты и каналы каждой ноды | `node_contacts`, `node_channels` |
| Идентичности контактов и каналов | `contact_identities`, `channel_identities` |
| Локальные настройки контактов | `contact_settings` |
| История CLI | `companion_cli_history`, `repeater_cli_history` |
| Пути, приём и доставка | `contact_path_history`, `contact_location_cache`, `heard_packets`, `delivery_observations` |
| Обнаруженные контакты и прочее состояние ноды | `discovered_contacts`, `node_state` |
| Wardrive | `wardrive_samples`, `wardrive_sessions`, `wardrive_uploads` |

Новая таблица для настроек не требуется: `contact_settings` уже содержала регион
отправки. Остальные локальные параметры добавляются как новые имена в ней.
Поля контакта из прошивки остаются в `node_contacts` и на самой ноде.

## Таблица contact_settings

```sql
CREATE TABLE IF NOT EXISTS contact_settings (
  node_key TEXT NOT NULL,
  contact_key TEXT NOT NULL,
  name TEXT NOT NULL,
  value TEXT NOT NULL,
  PRIMARY KEY (node_key, contact_key, name)
);
```

- `node_key` — существующая область хранения ноды: первые 10 hex-символов её
  публичного ключа. Сохраняется прежнее разделение настроек по нодам.
- `contact_key` — полный публичный ключ контакта в hex.
- `name` — имя отдельного параметра.
- `value` — значение этого параметра в текстовом представлении.

Каждому параметру соответствует отдельная строка. Вся конфигурация контакта
одним JSON-объектом не хранится. Список выбранных быстрых ответов кодируется
JSON-массивом строк, поскольку сам параметр имеет тип списка.

| name | Значение | Если не сохранено |
|---|---|---|
| `flood_region` | Имя региона / `*` без региона | Регион ноды |
| `mcmp_enabled` | `0` / `1` | Выключено |
| `mcmp_version` | `2` / `3` | `3` |
| `mcmp_use_sign` | `0` / `1` | Выключено |
| `mcotxt_enabled` | `0` / `1` | Выключено |
| `mcotxt_plain_when_smaller` | `0` / `1` | Включено |
| `smaz_enabled` | `0` / `1` | Выключено |
| `cyr2lat_enabled` | `0` / `1` | Выключено |
| `cyr2lat_profile` | Идентификатор профиля | Общий профиль |
| `sending_delay_enabled` | `0` / `1` | Выключено |
| `quick_answer_ids` | Массив идентификаторов | Пустой список |
| `url_images_enabled` | `0` / `1` | Выключено |

Избранное и разрешения телеметрии являются флагами контакта в прошивке, поэтому
в эти 11 локальных параметров не входят.

## Автоматический перенос

1. После открытия БД, до основного UI, приложение находит известные scoped-ключи
   `contact_*` в SharedPreferences и проверяет тип каждого значения.
2. Параметры всех нод переносятся в одной SQL-транзакции. Уже существующая строка
   SQL сохраняется, даже если её значение `false`, пустой текст или пустой список.
3. После успешного commit удаляются перенесённые ключи preferences. Если процесс
   прервётся до очистки, повторный запуск не перезапишет более свежие SQL-значения.
4. Значения БД загружаются в кеш до отображения основного UI. Первый вход в чат
   использует сохранённое сжатие без повторного открытия настроек.

Ошибка SQL откатывает импорт и оставляет исходные ключи для повторной попытки.
Невалидные и неизвестные ключи не удаляются. У самого старого SMAZ-ключа нет ноды;
он переносится при первом запросе подходящей реальной ноды с сохранением прежних
исключений миграции. Вручную запускать команду переноса не требуется.

Выбор способа сжатия сохраняет все четыре флага в одной транзакции. Кеш хранилища
обновляется после успешного commit, записи учитываются как незавершённая работа
при управлении сном CPU. При объединении истории контактов копируются только
отсутствующие параметры, а явные настройки нового контакта сохраняются.

Для Android/iOS/настольных приложений новые записи идут в SQLite. Браузерная
версия пока не использует эту БД, поэтому сохраняет прежний backend preferences.
Такой же fallback используется лёгкими тестами без инициализации БД.

## Проверки владельца

```powershell
Set-Location O:\_git\meshcore-open
$contactSettingsTests = @(
  'test/connector/contact_settings_persistence_test.dart'
  'test/storage/contact_settings_database_test.dart'
  'test/storage/stores_load_without_writes_test.dart'
)
flutter test @contactSettingsTests --exclude-tags=slow --reporter expanded
flutter analyze
```

SQL-тесты используют временный файл и настоящее повторное открытие соединения;
проверяют 11 параметров, изоляцию нод, копирование, повтор миграции, откат при
ошибке SQL и атомарность выбора сжатия. На устройстве дополнительно проверить
переход с прежних настроек, полное закрытие приложения и первый вход в чат.
Генерация Dart-файлов для этой правки не требуется.
