# Хранилище истории сообщений

На native-платформах история хранится в SQLite. Сообщения сохраняются с WAL
и `synchronous=FULL`: настройка энергосбережения не ослабляет подтверждение записи.

Для новой базы включается `auto_vacuum=INCREMENTAL` до настройки WAL и создания
таблиц. Этот режим позволяет существующему механизму обслуживания освобождать
страницы по явному запросу; он не означает полную перестройку после каждого
сообщения. Установка только в `onCreate` может оказаться слишком поздней для
уже инициализированного файла.

При открытии существующей базы её режим auto-vacuum сохраняется. Приложение
не запускает для этого автоматический `VACUUM`. В режиме `NONE` свободные
страницы после удаления остаются внутри файла и используются следующими
записями; отсутствие уменьшения файла само по себе не означает потерю данных.

Порядок и ограничения изменения auto-vacuum описаны в
[документации SQLite](https://www.sqlite.org/pragma.html#pragma_auto_vacuum).

Проверки создания базы и повторного открытия:
`test/storage/message_history_wal_test.dart`. Они используют временные файлы,
проверяют исходные WAL/FULL и сохранность строк; существующие данные пользователя
для тестирования не требуются.

Переключаемое сокращение перезаписи статистики доставки описано в
[энергосбережении](power-saving.md#сокращение-перезаписи-статистики-доставки).
Оно работает внутри одной транзакции и не меняет срок сохранения сообщений,
WAL/FULL или схему существующей базы.
