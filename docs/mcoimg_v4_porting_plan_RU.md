# План портирования MCOimg v4

Как MCOimg v4 получает порт на JavaScript, рядом с браузерным инструментарием
v3 в `docs/mcoimg-js`, и порт на C++, в прошивку компаньона South Edition
(`meshcore-luch/MeshCore`), и что должно быть готово до начала любого из них.
Порты v3 прошли ту же дорогу; их инструменты используются везде, где подходят.

## Эталон

- Формат — тот, что в теге `9.5.1-mod-1.9.0` этого репозитория:
  `lib/helpers/mcoimg_v4_codec.dart`, `lib/helpers/mcoimg_v4_model.dart` и, в
  нормативной части отрисовки, `lib/widgets/mco_image_v4_view.dart`. С момента
  тега эти файлы не менялись. Ничто более раннее эталоном не является, в том
  числе тег `v4-vector-stable`: он старше текстовой фигуры.
- [`mcoimg_v4_reference_RU.md`](mcoimg_v4_reference_RU.md) описывает этот код и
  сверен с ним утверждение за утверждением 2026-09-06. Где они всё ещё
  расходятся, главнее код, а документ исправляется.
- Текстовая фигура несёт поток MCOtxt v1:
  [`MCOTXT_V1_PROTOCOL_RU.md`](MCOTXT_V1_PROTOCOL_RU.md). Таблицы заморожены
  как поколение моделей `0` в `tools/MCOtxt/generated/model_manifest.json`
  (`"frozen": true`, семь языков); заголовки C лежат рядом с таблицами Dart в
  том же каталоге.
- Растровый слой несёт тело v3 без packet nonce:
  [`mcoimg_v3_reference_RU.md`](mcoimg_v3_reference_RU.md).
- Формат канонический, поэтому приёмка порта с кодером побайтовая: декодировать
  вектор, закодировать документ обратно, сравнить с байтами канонического
  документа. Порт с одним декодером вместо этого сравнивает свой дамп документа
  с эталонным.
- Порт обязан различать отказы так же, как эталон: повреждённый ввод — один
  класс, неподдерживаемое расширение (режим `2` или `3`, команда второго
  escape кроме `0`, поток MCOtxt, для которого у порта нет таблиц) — другой,
  потому что у них разные заглушки.

## Что уже есть

JavaScript, `docs/mcoimg-js`:

- `mcoimg-v3-codec.global.js` (`window.MCOImgV3`) содержит декодер и кодер v3,
  Base91 и хелперы прикладного конверта; `mcoimg-browser.global.js`
  диспетчеризует по версии; `mcoimg-v3-worker.global.js` выполняет разделы
  кодера в воркерах.
- В `tests/` 39 независимо написанных бинарных фикстур, генераторы Dart↔JS и
  `run-cross-runtime-tests.js`, который гоняет оба рантайма.
- MCOtxt на JavaScript пока нет.

C++, каталоги форка `src/helpers/mcoimg/` и `src/helpers/mcotxt/`:

- `MCOImgTransport` узнаёт текстовые `im:` / `imN:` и конверты `0x0120`, а
  версию `4` сегодня сообщает как `UnsupportedVersion`.
  `MCOImgDecoder::decodeV3` раскодирует тело v3 в `PixelStore` в пределах
  `MCOIMG_MAX_PIXELS`; `MCOImgRenderer` превращает фиксированные и динамические
  палитры в монохром порогом или дизерингом Байера.
- Таблицы палитр генерируются из этого репозитория скриптом
  `tools/generate_mcoimg_tables.py`; фикстуры декодера — скриптом
  `tools/generate_mcoimg_fixtures.py` в заголовок, который проверяют
  `tools/mcoimg_fixture_check.cpp` / `run_mcoimg_fixture_check.bat`.
- `MCOtxtCodec`, `MCOtxtModels` и `MCOtxtTransport` декодируют MCOtxt v1 по
  замороженным таблицам; рецепт переноса одного декодера в другую прошивку
  записан в README этого каталога. Base91 — `helpers/Base91.*`, помощники
  UTF-8 — `helpers/UTF8Helpers.h`.

## Предварительные шаги

В таком порядке. Шаги 3 и 4 блокируют порты; 5–7 можно вести параллельно с ними.

1. **Зафиксировать формат.** Сделано 2026-09-06: справочник называет своим
   источником тег релиза, режимы `2` и `3` зарезервированы, названы точки
   расширения и два класса отказов.
2. **Сделать `ELLIPSE_DEPTH` переносимым.** Сделано в справочнике 2026-09-06:
   целочисленная проверка (`L` целое, обе масштабированные координаты делятся
   на `2L`) — правило для порта, а проверка эталона в double с допуском `1e-9`
   показана принимающей те же потоки в координатном диапазоне формата.
   Необязательное продолжение в Dart: перевести кодек на целочисленную
   проверку, чтобы эквивалентность не требовала доказательства.
3. **Тесты на Dart для каждой команды.** `test/helpers/mcoimg_v4_text_test.dart`
   покрывает текстовую фигуру и больше ничего. В том же стиле добавить тесты на
   заголовок (каждый режим размеров и его отказы по каноничности,
   переопределение фона, каждый профиль), стилевые команды, каждую базовую
   фигуру, каждую альтернативную форму, каждую форму пути с покомпонентным
   escape, `DOT_RUN`, четыре команды повтора с цепочками и цветной серией,
   вложенные группы, документ `mixed` с растровым слоем, транспортный хвост и
   по одному отрицательному тесту на каждый пункт списка валидации в
   справочнике, с проверкой, в какой из двух классов отказа он попадает.
   Каждый положительный тест заодно закрепляет точные байты, которые выдаёт
   эталонный кодер; именно это превращает его в вектор.
4. **Векторы и эталонный дампер.** Утилита `dart run` рядом с
   `docs/mcoimg-js/tests/generate_v3_dart_fixtures.dart`, которая пишет набор
   фикстур в JSON из документов шага 3 и читает любое тело обратно в
   канонический дамп. Одна фикстура: имя; байты канонического документа;
   полное тело с nonce и, где есть, хвостом; MD5-идентичность; и либо дамп
   документа, либо ожидаемый класс отказа. Дамп — JSON-представление
   `MCOImageV4Document` с фигурами в порядке потока, цветами как профильными
   ссылками и разрешённым для каждой фигуры липким текстовым состоянием. Его
   форма определяется один раз, здесь, и оба порта печатают одно и то же.
5. **Разобранные примеры в справочнике.** Побитовые трассы по одной фигуре
   каждого вида и один документ целиком, сгенерированные утилитой шага 4,
   чтобы не расходиться с векторами.
6. **Зависимости по целям.** JavaScript нужен декодер MCOtxt v1 и его таблицы:
   научить `tools/MCOtxt/MCOtxt_model_trainer_with_diagnostics.py` выдавать
   таблицу на JavaScript рядом с Dart и C, а `verify_runtime_models.py`
   сверять её с манифестом. C++ нужен вход в декодер v3 без nonce для
   растровых слоёв; приписать к payload слоя нулевой байт nonce достаточно,
   потому что значение nonce декодер не читает, так что это может быть
   обёртка в одну строку. Оба порта пишут собственный битовый ридер и писатель
   с каноническими целочисленными примитивами.
7. **Решения, которых справочник не принимает.** Прошивка: как растеризовать
   векторы на монохромной панели e-ink, включая масштаб с холста до `256x256`
   на панель; что рисовать вместо текстовой фигуры без шрифта на ноде; лимиты
   на размер документа, число фигур и глубину вложенности групп без кучи;
   целые или фиксированная точка для кривых овалов и волн; вести ли растровые
   слои через существующий рендерер v3 или пропускать. Браузер: только
   декодер с рендерером или ещё кодер с редактором; договор API в духе
   `docs/mcoimg-js/PORTING_PLAN.md`; использовать ли воркеры при кодировании.

## Порт на JavaScript

1. `mcoimg-v4-codec.global.js` в `window.MCOImgV4`: битовый ридер и писатель,
   целочисленные примитивы, заголовок и размеры, поток команд со всеми
   альтернативными формами, повторы и группы, растровые слои через
   `MCOImgV3`, транспортный хвост, текст `im4:` поверх Base91,
   MD5-идентичность. Сначала декодер, принятый по векторам, и только затем
   любая работа над кодером.
2. `mcotxt.global.js`: декодер MCOtxt v1 с замороженными таблицами,
   проверенный по конформанс-случаям MCOtxt; кодер — только если браузерный
   редактор входит в объём.
3. Рендерер на canvas для `output: 'image' | 'png'` по нормативной геометрии,
   текст — тем шрифтом, что есть у страницы.
4. Кодер, если входит в объём: тот же набор кандидатов, что в Dart, с выбором
   кратчайшего; побайтово по векторам.
5. Диспетчеризация версии `4` в `mcoimg-browser.global.js`, переключатель в
   `index.html`, фикстуры v4 в `run-cross-runtime-tests.js`.

## Порт на C++

1. `MCOImgV4Decoder` в `src/helpers/mcoimg/` за флагом `WITH_MCOIMG_V4`,
   нормализованным в `OptionalFeatureFlags.h`, как у остальных возможностей:
   разбирает в ограниченный список фигур с той же валидацией и теми же двумя
   классами отказов, текст декодирует через `MCOtxtCodec` в общий scratch, а
   растровые слои отдаёт `decodeV3` с приписанным нулевым nonce.
2. `MCOImgTransport` направляет версию `4` в него вместо `UnsupportedVersion`;
   `ChatLogScreen` получает тип содержимого v4 рядом с v3.
3. Векторный растеризатор для e-ink-рендерера: линии, прямоугольники и пути
   целочисленными отрезками, овалы и квадратичные кривые разбиением, заливки
   строчной развёрткой с правилом non-zero, точки залитыми кругами и замена
   текста, выбранная в шаге 7 выше.
4. Фикстуры: `tools/generate_mcoimg_fixtures.py` учится выдавать векторы v4 во
   второй генерируемый заголовок, `tools/mcoimg_fixture_check.cpp` и нативная
   среда gtest получают проход по v4, а стоимость во флеше и ОЗУ измеряется так
   же, как измерялся порт MCOtxt.

## Кросс-рантаймовая проверка и документация

- Один прогон генератора даёт артефакты для Dart, JavaScript и C, таблицы и
  векторы одинаково, так что расходиться им негде.
- Каждый порт гоняет одни и те же векторы: `run-cross-runtime-tests.js` для
  JavaScript, проверка фикстур и gtest для C++.
- У каждого порта свой README: раскладка и API для `docs/mcoimg-js`, описание
  модуля в `src/helpers/mcoimg/README.md` форка, а «Состояние реализации» в
  справочнике называет, что поддерживает каждый порт.
