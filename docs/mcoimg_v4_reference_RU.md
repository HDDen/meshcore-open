# Справочник MCOimg v4

Статус: экспериментальная реализация до первого релиза. Формат v4 пока можно
менять без обратной совместимости. Реализована векторная секция; растровая
секция зарезервирована для следующего этапа.

## Назначение

MCOimg v4 хранит редактируемый набор векторных фигур в порядке их отрисовки.
Формат рассчитан на минимальный payload в MeshCore, а не на полную точность
универсальных SVG-редакторов. Холст ограничен `256x256`; при выводе изображение
может масштабироваться до любого размера. Новый векторный холст редактора по
умолчанию использует сетку `32x32`, но пользователь задаёт ширину и высоту до
начала рисования.

Векторный редактор позволяет загрузить растровую подложку, привести её к
выбранному профилю палитры и временно скрывать или показывать. Подложка нужна
только для обводки и не входит в документ или payload. При изменении сетки или
профиля палитры она пересчитывается из исходного загруженного файла.

Геометрические инструменты работают через контрольные точки, как на обычном
холсте: линия завершается второй точкой, прямоугольник, овал и волна —
третьей. Уже поставленные точки отображаются до завершения фигуры. Карандаш и
перемещение объектов остаются жестами перетаскивания; короткое нажатие
карандашом создаёт отдельную точку.

Отдельный инструмент «Ломаная» принимает произвольное число вершин. Контур
можно завершить открытым или замкнутым; нажатие на первую вершину после трёх
точек также замыкает его. Открытая ломаная с заливкой виртуально замыкается
только при заполнении, не добавляя замыкающий сегмент обводки.

Видимость фигуры является только временным состоянием редактора. Скрытые
фигуры не сериализуются и не восстанавливаются у получателя; порядок видимых
фигур в потоке одновременно задаёт их z-order.

## Транспорт MCO Advanced

V3 и v4 используют один официальный `group_data` app-data type:

- `data_type = 0x0120`;
- MCOimg subtype id: `0x01`;
- v3 version: `0x03`, packed byte `0x13`;
- v4 version: `0x04`, packed byte `0x14`.

Envelope:

```text
senderNameLength(varuint) | senderName(UTF-8) | subtypeVersion(u8) | v4Body
```

Клиент сначала разбирает subtype и version. Неизвестная версия MCOimg должна
показываться как неподдерживаемая картинка, а не декодироваться как v3.

Текстовое представление истории имеет вид `im4:` + Base91 от `v4Body`.

## Тело v4

```text
nonce(u8)
documentLength(byteVarUint7)
canonicalDocument(documentLength bytes)
transportTail(optional)
```

`documentLength` записывается в кратчайшей форме и не включает transport tail.
`nonce` меняется при новой передаче, но не является частью идентичности рисунка.

## Канонический документ

Все поля после заголовка упакованы младшими битами вперёд.

```text
mode(1)                         // 0 = vector, 1 = reserved raster
widthMinus1(8)
heightMinus1(8)
paletteProfile(4)
paletteCountMinus1(6)
palette[paletteCount]           // profileColorBits на элемент
hasBackground(1)
backgroundLocalIndex?           // paletteBits
hasDefaultFill(1)
defaultFillLocalIndex?          // paletteBits
hasDefaultStroke(1)
defaultStrokeLocalIndex?        // paletteBits
defaultStrokeWidthMinus1        // scalarBits
commandStream
END(4)
zero padding to byte boundary
```

```text
xBits      = max(1, bitLength(width - 1))
yBits      = max(1, bitLength(height - 1))
scalarBits = max(1, bitLength(max(width, height) - 1))
paletteBits = max(1, bitLength(paletteCount - 1))
profileColorBits = dynamic ? 9 : bitLength(profileColorCount - 1)
```

Координаты являются целыми индексами `0 .. axisSize - 1`. Лишние коды,
появившиеся из-за степени двойки, невалидны. Нормализации на весь диапазон
битового поля нет.

Палитра общая для документа и содержит от 1 до 64 уникальных цветов выбранного
профиля v3. Для фиксированного профиля элемент является его локальным color id;
для динамического — индексом `global512`, который обязан входить в выбранный
dynamic-профиль. Фигуры используют короткие локальные индексы палитры документа.

`paletteProfile` использует порядок `PaletteProfile`:

```text
0 mono                 8 grayscale8
1 master4              9 dynamicGlobal8
2 master8             10 dynamicGlobal16
3 master16            11 dynamicGlobal32
4 master32            12 dynamicGlobal64
5 master64            13 dynamicGlobal128
6 grayscale16         14 dynamicGlobal256
7 grayscale32         15 dynamicGlobal512
```

При выборе dynamic-профиля на 128–512 цветов редактор показывает весь профиль,
но добавляет в локальную палитру документа только выбранные цвета, максимум 64.
Новый v4-холст по умолчанию использует `Master 8`. Видимость сетки наследуется
из обычного холста v2/v3.

## Система координат и рендер

Точка `(x, y)` отображается в логическую позицию `(x + 0.5, y + 0.5)` внутри
прямоугольника холста `[0, width] x [0, height]`.

Для viewport:

```text
scale = min(viewportWidth / width, viewportHeight / height)
offsetX = (viewportWidth - width * scale) / 2
offsetY = (viewportHeight - height * scale) / 2
screenX = offsetX + (x + 0.5) * scale
screenY = offsetY + (y + 0.5) * scale
```

Рендерер обрезает вывод по границам холста, но не меняет геометрию. Координаты
опорных точек всегда находятся внутри холста. Сглаживание зависит от
реализации; геометрия, non-zero fill, квадратные торцы и острые miter-соединения
нормативны. Примитив точки остаётся круглым.

Прямоугольник и овал задаются контрольными точками на сетке центров ячеек.
Фоновая заливка задаётся отдельным цветом документа, поэтому площадным фигурам
не нужно специально дотягиваться заливкой до края холста.

## Стилевой автомат

В заголовке задаётся исходный стиль. Модель редактора хранит абсолютный стиль
каждой фигуры; энкодер пишет только изменения:

| opcode | команда |
| --- | --- |
| 0 | `END` |
| 1 | `SET_FILL` |
| 2 | `SET_STROKE` |
| 3 | `SET_STROKE_WIDTH` |
| 4 | `DOT` |
| 5 | `LINE` |
| 6 | `RECT` |
| 7 | `ELLIPSE` |
| 8 | зарезервировано |
| 9 | `PATH_ABSOLUTE` |
| 10 | `PATH_DELTA` |
| 11 | `WAVE` |
| 12 | `REPEAT_LAST` |
| 13-15 | зарезервированы |

Каждый opcode занимает 4 бита. Optional color записывается как `present(1)` и
локальный индекс палитры. Положительные скаляры записываются как `value - 1`.
Толщина 0 не представима; отсутствие контура задаётся `stroke = none`.

## Фигуры

- `DOT`: одна точка; диаметр равен толщине контура.
- `LINE`: начальная и конечная точки.
- `RECT`: три контрольные точки `A, C, B`; четвёртая вершина вычисляется как
  `D = A + C - B`.
- `ELLIPSE`: три контрольные точки. Первые две задают главную ось, третья
  задаёт полуось по перпендикуляру к главной оси.
- `PATH`: флаг `closed`, число точек и точки.
- `WAVE`: флаг `closed`, две конечные точки, знак и модуль глубины.

Открытый `PATH` или `WAVE` с заливкой виртуально замыкается только для заливки.
Замыкающий сегмент контура рисуется только при `closed = true`.

`WAVE` является quadratic Bezier. Глубина измеряется по нормали к хорде и
указывает положение видимой середины дуги; control point находится на удвоенной
глубине. Концы остаются на сетке центров ячеек.

## Пути

`pointCount` хранит `actualCount - minimum`, где minimum равен 2 для открытого
пути и 3 для закрытого. Используется bitCompactUint:

- `0 + 2 bits`: 0..3;
- `10 + 4 bits`: 4..19;
- `110 + 8 bits`: 20..275;
- `111 + bitVarUint7`: значения больше 275, только кратчайшая форма.

Энкодер сравнивает `PATH_ABSOLUTE` и четыре `PATH_DELTA` кандидата. Delta
кандидат содержит двухбитный selector для short width `3/4/5/6`. Первая точка
абсолютная. Каждая следующая X/Y-компонента содержит escape bit:

- `0`: ZigZag delta в short width;
- `1`: полная абсолютная координата оси.

Прореживание росчерка, RDP, квантование и удаление дублей/коллинеарных точек
являются ненормативной работой энкодера. Декодер восстанавливает ровно
переданный путь.

## REPEAT_LAST

Команда повторяет только геометрию последней выведенной фигуры со знаковым
смещением X/Y. Стиль берётся из текущего состояния автомата. Повтор может
следовать за повтором. Если результат вышел бы за допустимую геометрию,
энкодер обязан вывести полную фигуру.

## Transport tail и цитирование

Tail начинается с byte flags:

- bit 0: `targetNameLength(byteVarUint7) + targetName(UTF-8)`;
- bit 1: `replyTimestamp(uint32 LE)`;
- bits 2-7: зарезервированы и должны быть нулевыми.

Tail не входит в `documentLength` и не является частью документа. Он хранится в
сообщении, но удаляется при сохранении в галерею, image pack или `.mcoimg.bin`.

## Идентичность

Identity hash для pack tooling:

```text
MD5(0x14 | 0x00 | canonicalDocumentLength | canonicalDocument)
```

Длина остаётся в кратчайшей byteVarUint7 форме. Nonce и transport tail не
участвуют, поэтому один рисунок имеет одинаковый hash для разных получателей и
ответов.

## Валидация

Декодер работает fail-closed и отвергает документ целиком при:

- выходе за payload или некратчайшем varuint;
- неизвестном opcode или ненулевом padding;
- повторе без предыдущей фигуры;
- дублирующемся/невалидном цвете;
- ссылке вне палитры;
- координате вне оси или фигуре вне холста;
- нулевой/слишком большой положительной величине;
- недостаточном числе точек;
- неизвестных флагах transport tail.

Частично повреждённый рисунок не отображается.

## Состояние реализации

Реализованы Dart codec, vector renderer, редактор фигур, бинарная отправка и
приём, цитирование, стабильный identity hash, галерея и импорт/экспорт BIN/PNG.
Растровый mode, слои v3-кандидатов, опциональное удаление перекрытий и JS-порт
остаются отдельными следующими этапами.
